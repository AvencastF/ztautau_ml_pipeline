# Detector input converter (2026-10-12)

**Status correction, 2026-10-12:** the user requires input-only changes and unchanged EveNet Core/Align runtime. Our Core bool-dtype modification and three Align runtime modifications have been reversed with history-preserving reverts. Converter work and engineering evidence are retained, but the custom zero-global adapter training path described below is superseded and currently unavailable. Do not run its training wrapper/config until the converter emits the existing standard supervised format. Future scope is normal supervised classification and neutrino prediction; no DGPO/RL changes. The remaining sections record the earlier engineering contract/evidence, not current default-training readiness.

`build_evenet_input_from_parquet.py` fits/applies a missingness-aware feature contract for the additive `particle_detector` version1 Parquet payload. It replaces the absent documented converter entrance for this schema; legacy inputs are unsupported. The converter and normal streaming loader support **classification only**. Audited charge-ordered targets are constructed as described below; invisible, assignment, segmentation, generation and RL targets are unsupported. Original truth stays in source columns, outside model features. An approved train/validation/test split remains a prerequisite for production training.

All input Arrow columns, their order, physical types and metadata are retained as a prefix. Tensor columns are appended. Event identity, original signed weight (also copied to event_weight/central_weight), truth and the complete raw detector JSON remain available. No luminosity normalization is repeated. Region selection uses saved `regions` metadata and `region_mask`, or explicit `all`; no nprong or PDG selection is added. Particles use ascending original MAIN index, with all arrays aligned and indices saved; a trackless or zero-pT real particle remains present. Capacity overflow fails rather than truncating. Production capacity is an explicit caller decision, not established by the smoke sample.

## Feature and validity contract

Selected values are MAIN energy, derived pT/eta/phi, charge, mass; named ELID tag/conversion, MUID word/chi2/hit pattern, RPROCO pion/kaon/proton/heavy/electron/quality, all named MTPC and HAID fields listed in `detector_inputs.PID`; singleton-track chi2/ndf and track count; MAIN TrackLength/DetectorMask; and separate EMNC, HCNC, HCAL and SSTC shower counts, energy sums and mean Cartesian positions. Source units are preserved. Centroids are unweighted means over distinct linked shower indices, not fitted particle directions. These compact summaries avoid a variable-width shower encoder; HCNC and HCAL are never combined.

Detailed profiles, covariance/helix states, TOF, muon chamber arrays, PHOT/pi0/conversion graph details and other raw payload fields remain **raw-only** in the retained JSON. They are not claimed to be model features. MAIN.PDG and all truth-derived species are excluded from x.

Each selected value has stored_valid, measurement_known, measurement_valid and normalization_supported channels. A stored finite value with unknown semantic validity is available as raw information with explicit unknown flags; it is never certified as a measurement. Known-false values are excluded from fitted statistics and model value channels, but preserved in raw_detector_values. Derived values propagate false if any source is false, true only if every source is true, otherwise unknown. Missing/nonfinite values are unavailable; valid zero is retained. PID/track/calo association onehots distinguish linked, no_association, unavailable, malformed, ambiguous and known empty. Malformed or unavailable shower ancestry suppresses incomplete sums. Multiple singleton PID/track matches do not produce a guessed scalar.

Normalization is unweighted, feature-wise pooled centered moments over usable **training-only** values, including zeros. Charge remains raw. Features absent in training have support=false and zero model value even if present later. Frozen means/stds/counts, feature-order fingerprint, selection/capacity contract, source schema hashes and training identity digest are recorded. Fit rejects data; `--role train` and an owner-provided `--split-id` are mandatory. The converter does not create or independently certify disjoint splits: pass already approved training files only, then apply the same artifact to validation/test/data. Every generated backend normalization tag is `none`; do not run a second automatic normalization fit.

The current grouped encoder retains seven projected slots: four momentum, two learned detector slots and raw charge. Mask/status channels enter the detector group without normalization. Momentum missingness remains visible there; it never becomes particle padding. The bounded supervised check confirms classification forward/loss/backward/optimizer compatibility, not physics performance.

## Commands

Use an environment with the repository's dependencies and initialized submodules. Example (fresh outputs):

```sh
python build_evenet_input_from_parquet.py fit --input TRAIN.parquet --output TRAIN_features --normalization normalization.json --role train --split-id APPROVED_TRAIN --region all --max-particles CAPACITY --validation-features VALIDATION_features
python build_evenet_input_from_parquet.py apply --input VALIDATION.parquet --output VALIDATION_features --normalization normalization.json --role validation --split-id APPROVED_VALIDATION --region all --max-particles CAPACITY
# Training command unavailable pending standard-format input conversion
python smoke_detector_inputs.py TRAIN_features --rows 2
python test_detector_inputs.py
```

The normal Align `scripts.shared.make_process_fn` dispatches on the detector classification manifest, validates feature/class order, mapping, shapes, selection/capacity and frozen normalization, and invokes `load_tensor_batch` through Core `process_event_batch`. It loads only named tensor columns and restores explicit zero-width conditions with false conditions_mask. This preserves the established detector feature contract without inventing global measurements. A minimal Core bool-dtype fix permits the empty-global normalizer. The full default model successfully consumes it. Generated train_classification.yaml is a classification-only configuration; use the top-level wrapper to make the adapter importable in Ray workers. Explicit separate validation apply output is mandatory; automatic file splitting of already-normalized training shards and --load_all are rejected in this mode. Prediction keeps ineligible/data rows. Production runs still require the usual resource approval.

## Classification contract and supervised evidence

Class order is exactly `common.ordered_class_labels(config/analysis.yaml)`: seventeen configured tau classes followed by Zll and Zqq. Modern tau truth uses explicit plus/minus keys from `tau_analysis/analysis/truth.py`. Legacy `lep_tree_ana/utils/tau_decay.py` defines category tens as positive and units as negative. Mapping is pi=1, rho=2, e=3, mu=4 and known other_1prong/other_3prong/other_prong=5, then the existing Subcategories lookup selects the class. Unknown/missing/malformed truth receives target -1 and eligibility=false. No unordered truth string or reconstruction category determines the target.

Saved process aliases, verified against tau_analysis/configs/1994.yaml and production inventory, are Z_tautau→Ztautau, Z_ee/Z_mumu→Zll and Z_qq→Zqq. Data, Bhabha, yy_ll, yy_qq and other unmapped processes remain ineligible. Rejection reasons are retained as source-only classification_reason and manifest counts. Eligibility is bool, indices int64; inconsistent/out-of-range combinations fail before supervision. Normal supervised streaming filters ineligible rows before batching, explicitly rejects an all-ineligible dataset, and leaves unrelated dataset behavior unchanged. Source identities and signed weights are retained; default Training.apply_event_weight=false means the classification objective is unweighted by those event weights.

Class balance uses the existing Core compute_classification_balance on train-only eligible raw counts. Its existing count<1 clamp handles absent classes; classcounts/support are retained rather than claiming absent classes trained. External per-feature normalization remains frozen and all backend feature tags are none. The backend identity normalization artifact, classcounts/balance and configured engine artifact are validated together. Existing project GroupedSequentialEmbedding AdamW/projector settings are reused verbatim from config/train_pretrain.yaml so detector encoder parameters are optimized; remaining optimizer and loss defaults are unchanged. The generated config enables only classification, disables its diffusion cross-term and other heads, and disables external W&B logging/checkpoints by default. No RL/generation behavior is modified. Disabled segmentation imports are deferred until enabled, avoiding its CUDA assignment dependency in classification-only CPU execution.
